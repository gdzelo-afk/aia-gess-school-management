# 0004 — Timetable publication and occurrences

Status: accepted for Stage 1B; builds on the Stage 1A transaction/identity model.

A timetable version is a bounded aggregate document for one academic year and an inclusive-start/exclusive-end interval. It contains configurable local bell periods, teaching groups and recurring Monday–Friday lessons. JSONB keeps a complete editable/published document together; Zod bounds and validates it, and the service validates every Stage 1A identity/reference. This is not generic table CRUD. No automatic generator, A/B week cycle, co-teaching or block periods.

A teaching group references one or more Stage 1A offerings of the same subject. Each source either uses its complete effective roster or an explicit pupil-ID subset intersected with that roster. Thus split groups, cross-section electives and a single combined-section lesson share one interpretation. Elective membership and section enrollment remain Stage 1A's dated records, not copied membership tables. The subset itself is versioned with the timetable.

Publishing rechecks the complete effective date range under the existing administration lock, requires each overridable conflict's exact digest and reason, snapshots display labels, and freezes the version. Invalid employment, offering or assignment relationships are hard errors; teacher/room/student overlap and availability are explicit, audited override decisions. A later version wins from its configured start within its interval; outside that interval the previous applicable version remains effective. Administrators must choose end dates deliberately. Database triggers reject changes/deletion of published versions and exceptions.

Occurrence identity is `versionId:lessonId:sourceSchoolDate`. Resolution combines the effective publication, date-only Stage 1A rosters/calendar and latest append-only exception. A move retains that identity and records a different target date/time. The exception UUID (or source fingerprint) is the optimistic occurrence revision; an identity sequence orders exceptions without timestamp-tie ambiguity. Calendar holidays/vacations suppress normal lessons. Explicit special-day action can instantiate a template lesson on a different weekday or non-teaching date. Cancelled lessons remain visible as cancelled. Attendance will reference this resolver/identity in Stage 1C; no attendance records exist now.

Availability is separate from HR attendance. Administrators enter recurring or date-specific constraints; teachers request their own dated absences. Approval checks captured occurrence revisions, covers every affected absence lesson and commits exceptions, availability, decision and audit atomically. Substitutes need active staff/account eligibility, not permanent course assignment. They gain only their actual timetable occurrence scope, not broad student-directory access.

Read requests are bounded to fourteen days, authorize identity scope on the server, and batch domain reads without per-lesson database calls. The aggregate approach is suitable for one school's scale; normalized slot indexes or materialization can be introduced if measured workloads require them. No Redis or separate service.
